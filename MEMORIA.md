# Memoria de Proyecto: Museo QR Web

## 1. Estado Técnico Actual
- **Aplicación:** PWA Web Móvil para visitantes de museo (5 salas) mediante códigos QR físicos.
- **Stack:** Vite + React (TypeScript) + CSS puro con design tokens + `@supabase/supabase-js` + `lucide-react` + `qrcode.react`.
- **Datos:** salas dinámicas desde la tabla `rooms` de Supabase (RF-08) con fallback automático a `museumData.ts`; credenciales en `.env` (plantilla en `.env.example`).
- **Estructura clave:** `src/App.tsx` (estado global, Auth y enrutamiento), `src/lib/routing.ts` (detección de rutas), `src/lib/supabase.ts` (cliente + Auth), `src/lib/serviceWorker.ts` (registro del Service Worker, RF-15), `src/services/roomsService.ts` (lectura), `src/services/adminService.ts` (escritura con sesión + Storage), `src/services/settingsService.ts` (taquilla: lectura pública y escritura autenticada), `src/services/offlineStorage.ts` (respaldo local de salas y taquilla, RF-15), `public/sw.js` (Service Worker: precaché del shell y estrategias, RF-15), `src/components/` (`CabeceraApp`, `MenuSalas`, `DetalleSala`, `SalaNoEncontrada`, `VistaCarga`, `GeneradorQR`, `TicketPaymentView`), `src/components/admin/` (`AccesoAdmin`, `PanelAdmin`, `EditorPiezas`, `EditorTaquilla`, `idiomas.ts`), `src/i18n/textosUI.ts` (textos de interfaz), `src/data/museumData.ts` (fallback con salas y piezas), `src/types.ts`, `src/index.css`, `supabase/exhibits.sql` y `supabase/museum_settings.sql` (esquemas), `vercel.json` (reescritura de rutas y cabeceras de `/sw.js`).
- **Calidad:** `npm run build` (`tsc -b && vite build`) y `npm run lint` (oxlint) en verde.
- **Estándares:** SDD (todo cambio se especifica primero en `SPEC.md`), tipado estricto, estado local con `useState` y detección de URL con `URLSearchParams`.

  - **Dos bugs detectados en la prueba de modo avión y corregidos:**
    1. **`Vary: Origin`:** Vite añade `crossorigin` al script **y** al stylesheet, y las respuestas llevan `Vary: Origin`; la petición del navegador incluye la cabecera `Origin` pero la entrada guardada desde una URL puede no incluirla, así que el `match` fallaba justo para las peticiones del parser → la app quedaba en negro (502 en `/assets/*`). Corregido con **`ignoreVary: true`** en todos los matches.
    2. **502 del proxy:** en local, con el servidor detenido, el proxy devuelve **502** en lugar de rechazar la petición (`fetch` no lanza), así que la app recibía el error del proxy en vez de su caché. Corregido con **`esFalloDeRed()`** (502/503/504 → fallo de red) en las tres estrategias.
  - **Hallazgo sobre `skipWaiting`:** comprobado en el navegador que una versión en espera **no** se activa recargando la página, sino únicamente al cerrar todas las pestañas (inaceptable para un kiosco siempre abierto, RF-09); por eso el SW usa `skipWaiting()` + `clients.claim()` y **jamás fuerza `location.reload()`**: una versión nueva toma el control sin romper la sesión de admin (RF-10), la ruta `/?view=pago` (RF-14) ni el scroll/idioma.
  - **Registro seguro (`src/lib/serviceWorker.ts`, llamado desde `main.tsx`):** solo en producción (`import.meta.env.PROD`, para no interferir con el HMR de `npm run dev`), en contexto seguro (`'serviceWorker' in navigator` + `isSecureContext`), con `scope: '/'` e idempotente; `registration.update()` al volver la pestaña a primer plano (`visibilitychange`) con **aviso por consola** sin recarga; un fallo de registro solo genera `console.warn`.
  - **Respaldo local (`src/services/offlineStorage.ts`):** claves versionadas `museoqr:rooms:v1` y `museoqr:settings:v1` con forma `{ savedAt, data }`; lectura validada (JSON corrupto o forma inválida → `null`) y escritura en `try/catch` (modo incógnito o cuota llena → se omite). Solo se copian **datos reales de Supabase**, nunca `museumData.ts`. `roomsService.ts` y `settingsService.ts` integran el respaldo: sin conexión el orden es **copia local → `museumData.ts`**, y la taquilla devuelve la copia marcada **`fromCache: true`** (`SettingsReadResult`).
  - **Taquilla sin conexión:** `TicketPaymentView` muestra el aviso **`avisoSinConexion`** (nueva clave en `TextosUI`, 4 idiomas): *«Sin conexión: mostramos los datos guardados en tu última visita. El pago en línea (por ejemplo, Mercado Pago) requiere internet.»* y **oculta el botón «Pagar en línea»** (la copia de `payment_link` no sirve para pagar); precio, QR y «Copiar CLABE»/«Copiar monto exacto» siguen funcionando (son locales). Estilo nuevo `.taquilla-offline` en `index.css`.
  - **Vercel:** `vercel.json` fija `Cache-Control: public, max-age=0, must-revalidate` para `/sw.js` para que el navegador detecte cada deploy (SPEC §6).
  - **Pasos de prueba en modo avión / DevTools → Offline** (el SW solo se registra en producción, así que requieren `npm run build` + `npm run preview`, no `npm run dev`):
    1. Cargar la app online al menos una vez → DevTools → Application → Service Workers: estado `activated`; Application → Cache Storage: `museoqr-v1` con shell + assets; y en Application → Local Storage las claves `museoqr:rooms:v1` / `museoqr:settings:v1`.
    2. **Modo avión** (o DevTools → Network → Offline, o detener el servidor local) y **recargar**: el menú de salas debe renderizar sin errores de consola ni pantalla en negro.
    3. Abrir `/?view=pago` sin conexión: debe verse el aviso `.taquilla-offline` y **no** el botón «Pagar en línea»; «Copiar CLABE» y «Copiar monto» deben seguir operativos.
    4. Abrir `/?view=admin` sin conexión: debe verse el login (no pantalla en negro).
    5. Borrar las cachés de la aplicación (Application → Cache Storage → Delete) con el servidor caído y recargar: debe aparecer la página **«Sin conexión»** con el botón Reintentar.
